# 04 输出格式

> 本文件管：每天提交到 GitHub 仓库的数据文件（`data/daily/` 日报 JSON、`data/runs/` 采集日志）的结构与字段写法、提交前的自动检查、网站展示约定、历史数据迁移。
> 收不收见 `02`，归哪类见 `03`，周度总结文件见 `05`。

## 1 文件与路径

| 文件 | 路径 | 说明 |
|---|---|---|
| 日报数据 | `data/daily/YYYY-MM-DD.json` | 一天一个文件，**工作日必须有**（0 条也写，`status = none`）；周六日不生成 |
| 采集日志 | `data/runs/YYYY-MM-DD.json` | 全部候选及落选原因、查询与巡检记录；与日报一一对应 |
| 周度总结 | `data/weekly/YYYY-MM-DD_YYYY-MM-DD.json` | 见 `05` |

## 2 日报 JSON 结构

```json
{
  "date": "YYYY-MM-DD",
  "status": "normal | few | none",
  "highlights": ["今日精华要点（纯文本，无分类标签、无编号，1–3 条，≤ 条目数）"],
  "entries": [
    {
      "id": "YYYY-MM-DD-01",
      "category": "行业政策|行业方法论|新技术|市场动态|舆情|平台动态",
      "secondary_category": "选填，至多 1 个副类，取值同 category 且 ≠ category",
      "platform": "主类或副类为平台动态时填，如 豆包 / Google / ChatGPT / 多平台",
      "platform_topic": "主类或副类为平台动态时填：引用与呈现|检索与收录|爬虫与抓取|广告与商业化|购物与交易|测量与数据|规则与治理",
      "region": "国内|海外",
      "title": "一句话标题（平台动态须含平台名）",
      "summary": "核心内容一句话，≤150 字",
      "insight": "关注点：对 GEO 方案商有什么用，一句话",
      "published": "YYYY-MM-DD（主链接页面标注的发布日期）",
      "links": [{"text": "媒体名或标题", "url": "https://…"}],
      "source_type": "官方|中立媒体|企业发布稿|一手研究",
      "soft_class": "无|B|C"
    }
  ],
  "run": {"candidates": 0, "selected": 0, "domestic_ratio": 0.0, "domestic_ratio_30d": 0.0, "websearch_calls": 0, "webfetch_calls": 0}
}
```
仅历史迁移文件另有：顶层 `"legacy": true`、条目级 `"backfilled": true`（见第 8 节）。

## 3 字段规则

### 3.1 顶层字段
| 字段 | 规则 |
|---|---|
| `date` | 本份日报所属日期 D，必须与文件名一致 |
| `status` | `normal`：3–6 条；`few`：1–2 条，网站提示"今日 GEO 时效性动态较少"；`none`：0 条（`entries = []`、`highlights = []`），网站显示"今日无新增 GEO 行业动态（已执行全量检索）" |
| `highlights` | 今日精华，写法见 4.1 |
| `entries` | 当日条目，按**重要性**排序展示（`02` 6.1） |
| `run` | `candidates` = 进入核验的候选总数；`selected` = 入报条数（= `entries` 长度）；`domestic_ratio` = 当日 `region` 为国内的条目占比（0–1 小数，`none` 日记 0）；`domestic_ratio_30d` = 近 30 个自然日全部日报条目中 `region` 为国内的占比；`websearch_calls` / `webfetch_calls` = 实际调用次数，如实统计 |

### 3.2 条目字段
| 字段 | 规则 |
|---|---|
| `id` | `YYYY-MM-DD-NN`，NN 两位序号，从 01 起无缺号，与 `entries` 顺序一致，日期部分 = `date` |
| `category` | 主类，6 个固定值之一（`03` 第 1 节，冲突按 1.5 裁决），必填；统计口径一律按主类 |
| `secondary_category` | 副类，选填，至多 1 个，6 个固定值之一且 ≠ `category`；仅当原文含另一类的独立实质事实时填（`03` 第 1A 节），不填则省略或空字符串 |
| `platform` | 主类或副类为平台动态时必填，取值见 `03` 第 3 节；主类为平台动态时标题须含平台名，副类为平台动态时标题或摘要须含平台名 |
| `platform_topic` | 平台动态子标签，主类或副类为平台动态时必填，取值见 `03` 第 3A 节；其他条目不填 |
| `region` | `国内` 或 `海外`，= **事件主体所属市场**（国内平台 / 政策 / 企业 → 国内；Google、ChatGPT 等海外平台或机构 → 海外），与链接域名无关 |
| `title` | 一句话中文标题，概括事件本身，不带分类标签，不写营销口吻；平台动态须含平台名；B 类保留企业发布稿时标题或摘要须含「（信源为企业发布稿）」 |
| `summary` | 核心内容一句话，**≤150 字**（含标点），提炼要点不展开（教训：曾膨胀到 410 字） |
| `insight` | 关注点，一句话：从"我是 GEO 方案商"出发，回答对产品方向 / 交付方式 / 监测口径 / 向客户卖进话术有什么启示；具体，不写"值得关注"之类空话 |
| `published` | `YYYY-MM-DD`，**主链接（`links[0]`）页面标注的发布日期**，须在窗口内（`02` 1.3） |
| `links` | 数组 `{text, url}`，至少 1 条；`text` 为媒体名或标题；`url` 为检索工具实际返回的原始 URL。`links[0]` 为主链接；辅助链接只需与事件直接对应 |
| `source_type` | `官方`（平台 / 政府 / 标准发布方）、`中立媒体`、`企业发布稿`、`一手研究`；取主链接的类型（B 类换源成功则取新源类型） |
| `soft_class` | `无`（中立媒体报道或官方发布）、`B`（软文外壳 + 事实内核，含换源成功入报的）、`C`（一手实测 / 研究）；A 类整条删除，不进 `entries`（`02` 第 5 节） |

## 4 文字类字段的写法

### 4.1 今日精华 `highlights`
对当日全部条目做"趋势级"提炼：
1. **收敛归纳优先**：多条指向同一趋势 / 主题时，合成 1–3 条概括性、带判断、面向方案商的要点，不逐条复述标题。
2. **独立则逐条**：条目少（≤ 3 条）且主题互异时，每条一个分点。
3. **纯文本、无标签、无编号**：严禁 `[分类]` / `【平台动态-…】`、①②③ / `1)` / `1.` / （一）等前缀（教训：曾误加 ①②③ 被用户批评）；不含链接和 Markdown。
4. **1–3 条且 ≤ 条目数；条目 ≥ 1 时（1 条也）必填**；`entries` 为空时为空数组。
5. 写入时就不加，**不再静默剥离，而是由程序拦截**（C14）。

### 4.2 展示
网站对每条显著展示 `published` 与 `category`，方便判断新旧与主题。

## 5 采集日志与统计口径

### 5.1 采集日志 `data/runs/YYYY-MM-DD.json`
```json
{
  "date": "YYYY-MM-DD",
  "window": ["S", "D"],
  "candidates": [
    {
      "title": "", "url": "", "source": "", "published": "YYYY-MM-DD",
      "region": "国内|海外", "category_guess": "",
      "soft_class": "无|A|B|C|矩阵|未分级",
      "decision": "selected | rejected | unverified",
      "geo_relevance": "入选必填：一句话写明影响 02 第 0A 节 (a)/(b)/(c) 哪一项及如何影响，基于原文事实",
      "category_reason": "入选必填：一句话写明主类依据（核心事实、按 03 1.5 哪条裁决），有副类时一并写副类依据",
      "reject_reason": "超窗|日期无法确认|长青文|重复(历史)|重复(同源多投)|A类软文|矩阵软文换源失败|禁采域名|聚合页|疑似不可访问|文不对题|404|无独立链接|与GEO无关|平台通用履约排除|其他",
      "entry_id": "入报则填 YYYY-MM-DD-NN",
      "also_reported_by": ["其他报道 URL"],
      "found_via": "搜索:<查询词> 或 巡检:<页面>"
    }
  ],
  "source_swaps": [{"candidate": "", "query": "换源检索词", "result": "换到的独立源 URL 或 失败"}],
  "search_log": [{"query": "", "mode": "extended|standard", "region": "国内|海外", "useful": 0}],
  "channel_log": [{"page": "https://…", "status": "可用|打不开|需JS|无日期|robots禁止|需授权", "hits": 0}],
  "fetch_blocked": [{"url": "https://…", "by": "main|A|B|C|D", "note": "被拦原因，如 PROVENANCE_REQUIRED / 需批准 / 权限请求超时；以及后续处理（换源结果或候选不收）"}],
  "cell_notes": {"平台动态·国内": "找到了什么，或：确实没有 / 可能没搜到"},
  "audit": {"warnings": [], "domestic_ratio": 0.0, "domestic_ratio_30d": 0.0},
  "stats": {"websearch_calls": 0, "webfetch_calls": 0, "candidates": 0, "selected": 0},
  "notes": "无动态日填：已执行全量检索，窗口内无符合铁律的净新条目…"
}
```
要点：`geo_relevance`、`category_reason` 对 `decision=selected` 的候选必填（字符串），落选可省略，旧日志（legacy）不要求，`category_reason` 自 2026-10-27 的运行起要求；被拒候选（含 A 类、换源失败、不可访问）必须记原因；B 类 / 矩阵软文的换源检索必须进 `source_swaps`（证明已履行换源义务）；`cell_notes` 覆盖 12 格；`stats` 与日报 `run` 一致。
`channel_log.status` 取值：`可用|打不开|需JS|无日期|robots禁止|需授权`，其中「需授权」指 WebFetch 返回需用户批准 / PROVENANCE_REQUIRED / 权限请求超时，该页已跳过。
`fetch_blocked`（数组，无拦截时为空数组）：记录所有被平台"打开网址需批准"机制拦截的 URL，元素 `{url, by, note}`——`url` 为被拦网址原样，`by` 为谁遇到的（`main` 主会话，或子代理组字母 `A`–`D`；正常情况下网页只由主会话打开，故应为 `main`），`note` 写拦截提示与后续处理（换用了哪个独立来源核验，或"无可核验来源，候选不收"）。被拦 URL 不得作为入选条目的主链接。

### 5.2 `domestic_ratio` 口径
- 分子：`region = 国内` 的条目数；分母：条目数（`none` 日记 0）。当日值与近 30 日滚动值都记录。
- 任一值 < **40%** 只告警不拦截（`02` 4.4）；`none` 日不触发当日告警。

## 6 程序自动检查项（提交前由脚本拦截）

> **运行时 AI 必须预检，写入前就自行满足，不要等被拦截。**脚本只读规则文件与 `config/sources.json`，不改数据。**阻断** = 拒绝提交，不改动任何已发布数据；**告警** = 打印提示，不拦截。

### 6.1 检查清单
| 编号 | 检查项 | 处置 |
|---|---|---|
| C01 | JSON 可解析；顶层必填字段齐全（`date` `status` `highlights` `entries` `run`）；文件名日期 = `date` | 阻断 |
| C02 | `status` 与条数一致：none ⇔ 0；few ⇔ 1–2；normal ⇔ 3–6 | 阻断（> 6 见 C20） |
| C03 | 条目必填字段非空：`id` `category` `region` `title` `summary` `insight` `published` `links` `source_type` `soft_class`；平台动态须有 `platform` | 阻断 |
| C04 | `category` ∈ 6 个固定值（防"分类索引整体落空"类事故） | 阻断 |
| C05 | `id` 格式正确、日期部分 = `date`、唯一、序号连续 | 阻断 |
| C06 | 同日 (date, title) 不重复 | 阻断 |
| C07 | `summary` ≤ 150 字符 | 阻断 |
| C08 | `published` 为合法日期，∈ [S, date]（S 由脚本按 `02` 第 7 节据历史文件推算） | 阻断 |
| C09 | 每条 `links` 至少 1 条（`status = none` 豁免） | 阻断 |
| C10 | `links[].url` 以 `http://` 或 `https://` 开头、`text` 非空，且为原始 URL（不含 8.3 所述被清洗的参数） | 阻断 |
| C11 | 禁采域名 / 路径命中（清单见 `01` 第 7 节） | 阻断 |
| C12 | 聚合页 / 追踪站被用作信源（清单见 `01`） | 阻断 |
| C13 | 同一 URL（忽略查询参数）被 ≥ 2 条不同消息共用，比较范围 = 全部历史 + 当日 | 阻断 |
| C14 | `highlights`：条目 ≥ 1 时 1–3 条且 ≤ 条目数（`none` 日为空数组）；不以分类标签 / 编号开头；不含 Markdown 链接 | 阻断 |
| C15 | 平台动态：`platform` 非空且 ∈ `03` 3.1 取值，`title` 含该平台名或别名 | 阻断 |
| C16 | `soft_class = B` 且 `source_type = 企业发布稿` 时，标题或摘要含「（信源为企业发布稿）」 | 阻断 |
| C17 | `region` ∈ {国内, 海外}；`source_type` ∈ 4 值；`soft_class` ∈ {无, B, C}（出现 A 视为违规） | 阻断 |
| C18 | `run.selected` = `entries` 长度；`run.domestic_ratio` 与按 `region` 重算结果一致（容差 0.01） | 阻断 |
| C19 | `domestic_ratio` 或 `domestic_ratio_30d` < 40% → `ALERT·国内占比偏低` | 告警 |
| C20 | 当日条数 > 6；`date` 为周末；`run.candidates` < `selected` | 告警 |
| C21 | `legacy` 文件命中豁免项 → `WARN·历史豁免` | 告警 |
| C22 | `region = 国内` 但 `links` 全无国内域名（判定见 `01` 第 7 节） | 告警 |
| C23 | `secondary_category`（如填）∈ 6 个固定值且 ≠ `category` | 阻断 |
| C24 | 主类或副类为平台动态：`platform` 合法、`platform_topic` ∈ `03` 3A 取值；副类为平台动态时标题或摘要含平台名；非平台动态条目不得填 `platform_topic`（legacy 文件缺 `platform_topic` 豁免） | 阻断 |
| C25 | 分类线索提示：标题含融资词（融资 / 种子轮 / 天使轮 / A 轮 / raises / Series 等）但主类与副类都不是市场动态 | 告警（提示复核；确属"顺带提及既往融资"可不改，在 `category_reason` 说明） |

### 6.2 全局断言（渲染 / 发布前）
- 打印 6 类各自条数；若某类在源数据中有条目但统计为 0，视为解析错位，**中止，不写回**。
- 日期列表严格倒序；`data/daily` 文件名日期互不重复。

### 6.3 legacy 豁免（无 rebase）
新仓库从**干净基线**起步，不设违规基线文件。历史迁移文件在迁移时**一次性**标 `legacy`（8.4）；日常不提供 rebase / 重建基线操作，基线之外的新违规一律硬阻断，宁可日报不发，也不让劣化信源进入网站。

## 7 网站展示约定（供前端参考，非采集规则）

1. **每日动态页**：按日期倒序；按月份分组（`YYYY年M月`）；每日块标题 `YYYY-MM-DD（周X）`；块内先"今日精华"（`highlights`；历史无精华的日期回退显示条目标题），再逐条编号（按 `id` 顺序）。每条显示：分类标签（`平台动态` 显示【平台动态-<platform>】并附 `platform_topic` 子标签，其余显示 [分类]；有副类时在主标签后附「兼 <副类>」）、标题、发布日期（`published` 为空则不显示）、内容（`summary`）、关注点（`insight`）、链接（多链接并排）。`few` 在页面顶部提示"今日 GEO 时效性动态较少"；`none` 显示"今日无新增 GEO 行业动态（已执行全量检索）"。
2. **分类索引页**：6 类固定顺序（行业政策 / 行业方法论 / 新技术 / 市场动态 / 舆情 / 平台动态）；类内按日期倒序；条目在主类与副类下都出现，副类下的条目标「兼」，分类计数显示为「主类条数 + 兼类条数」；平台动态类可按 `platform_topic` 子标签筛选；每条先标题（带日期），其下各信源链接**每个独立一行**；`none` 日不进索引；**无条目的分类显示"（暂无收录）"**。每日动态页的分类筛选同时匹配主类与副类。
3. **今日精华永不带分类标签**（展示层也不补）。
4. **固定文案**：分类说明（`03` 第 4 节 C_CAT）、信源筛选原则（`02` 第 8 节 C_SRC）原样展示，不改一字；阅读指引、周结说明等其他固定文案由网站设计另定。

## 8 历史数据迁移（`GEO每日动态_数据.md` 共 145 条 → `data/daily/*.json`）

### 8.1 解析（逐行扫描）
| 行格式（正则） | 含义 |
|---|---|
| `^###\s+(\d{4}-\d{2}-\d{2})\s*\|\s*([^\|]+?)\s*\|\s*(.+?)\s*$` | 新建一条：date / cat / title |
| `^###\s+(\d{4}-\d{2}-\d{2})\s*\|\s*精华\s*$` | 该日精华块：其下 `- `（非 `- [`）行为精华分点 |
| `^摘要[：:]\s*(.*)$` | 当前条目 summary |
| 行以 `- [` 开头，用 `\[([^\]]+)\]\((https?://[^)\s]+)\)` 逐个提取 | 当前条目 links |
| 其余行（含文件头 `<!-- GEO_DATA v1 … -->`） | 忽略 |

日期块不一定按日期顺序，迁移时按日期分组，组内保持原出现顺序；同 (date, title) 只保留首条。

### 8.2 字段映射
| 原数据 | 新字段 | 处理 |
|---|---|---|
| 日期 | 文件名与 `date` | 一天一个文件 |
| 分类 / 标题 / 摘要 | `category` / `title` / `summary` | 原样；非法分类按 `03` 1.2 归舆情 |
| `- [文字](url…)` | `links` | 清洗 URL（8.3） |
| 当日出现顺序 | `id` | `YYYY-MM-DD-NN`，从 01 递增 |
| `### 日期 \| 精华` 的 `- ` 行 | `highlights` | 原样；含分类标签 / 序号前缀的按 4.1 一次性剥离。**无精华块的日期 `highlights = []`，不造精华**，网站回退显示条目标题 |
| `### 日期 \| 无动态 \| …` 哨兵 | `status = none`、`entries = []`、`highlights = []` | 哨兵文字存入 `data/runs/日期.json` 的 `notes` |
| 条数 | `status` | 0 → none；1–2 → few；≥ 3 → normal |
| （无）`insight` / `region` / `source_type` / `soft_class` | 同名字段 | **AI 基于原标题与摘要补齐，不联网**；条目标 `"backfilled": true` |
| （无）`published` | `published` | 能从原链接 / 上下文确定则填；否则 `null`。**不要拿块日期冒充** |
