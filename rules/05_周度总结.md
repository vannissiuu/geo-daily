# 05 周度总结

> 本文件管：每周一生成"上周"周度总结的触发条件、自愈补跑、四段内容的写法、`data/weekly/*.json` 格式与自动检查、历史周结迁移。
> 素材全部来自 `data/daily/*.json`（见 `04`），分类含义见 `03`。

## 1 触发与范围

1.1 每次运行先获取当天日期与星期。**仅当天是周一**时，除常规日报外额外生成针对**上周**的周结；非周一不生成、不改动任何周结文件。
1.2 上周 = 上周一至上周日（完整 7 天）：上周一 = 本周一 − 7 天，上周日 = 本周一 − 1 天。筛选依据是 `data/daily/` 中 `date`（日报所属日期）落在该区间的条目，**不是 `published`**。
1.3 周一当天日报可少发 / 记无动态，**周结照常生成**。整周 0 条时同样生成：`total = 0`，`trends` 可为空数组，并在 `overview.note` 注明"本周无新增动态"。
1.4 周结内容全部来自已落盘的日报 JSON，链接已核验，直接复用，**无需联网**，不得引入数据文件之外的新事实。只写入仓库（`data/weekly/`），不单独推送。

## 2 周结自愈补跑（最多补 1 份）

2.1 生成"上周"周结**之前**，检查 `data/weekly/{本周一−14 天}_{本周一−8 天}.json` 是否存在。
2.2 不存在（该周因离线漏跑未生成）则先补这一份（素材为日报日期落在该区间的条目，写法同第 3 节），再生成"上周"周结。**最多只补紧邻上一份**，更早的不回溯。

## 3 内容结构（用户已确认，不可更改）

只有**四段**，缺一不可，不得增加其他段；**严禁**"按分类罗列当周最重要动态"这类逐条罗列段。周结站点标题：`{上周一}至{上周日} 周度总结`。周度总结页按周倒序，最新周在最上。

| 段 | JSON 字段 | 站点标题 |
|---|---|---|
| ① 当周数据概览 | `overview` | 当周数据概览 |
| ② 趋势研判 | `trends` | 趋势研判 |
| ③ 平台逻辑变更综述 | `platform_changes` | 平台逻辑变更综述 |
| ④ 启示 | `implications` | 对 GEO 方案商的产品 / 销售启示 |

### 3.1 ① 当周数据概览
覆盖区间、总条数 `total`、6 个分类各自条数与占比；`by_category` 必须列全 6 类，某类 0 条写 `count: 0, pct: 0`；占比 = 该类条数 / `total`（`total = 0` 时全为 0）。站点示意：`覆盖 2026-09-14 ~ 2026-09-20，共 8 条`，其下每类一行"行业政策：2 条（25%）"。

### 3.2 ② 趋势研判
- **3–5 条**当周核心趋势，每条 `text` 一句话：概括性、带判断、面向方案商视角；**不加分类前缀**，不以编号开头。
- 每条 `refs` 为该周内 **1–3 个**代表性条目 `id`。条目有多个链接时，渲染取 `links[0]`。
- **渲染格式（用户已确认）**：① 每条趋势用**无序列表**，**绝不可用有序列表**（会误导为排序 / 步骤）；② 趋势文字下方直接列出 `refs` 对应原消息，每条就是一行带跳转超链接的标题（链接文字 = 条目 `title`，URL = `links[0].url`）；③ 这些信源行**不加列表点**，独立成行，不写成"日期 + 标题 + 信源"的冗余格式；④ 趋势与信源之间、不同趋势之间留间距。

### 3.3 ③ 平台逻辑变更综述
- 把当周"平台动态"条目串成一条线，按四个维度归纳：`信源引用逻辑` / `收录周期` / `生态绑定` / `爬虫可发现性`。每个维度一项 `{dimension, text, refs}`，`refs` 为 **1–2 个**代表性条目 `id`（渲染同趋势研判）。
- 某维度当周无相关变化：`text` 写"本周无重大…被记录"之类说明（如"本周无重大 robots / crawler 协议调整被记录"），`refs` 为空数组。
- 当周**没有任何平台动态条目**：`platform_changes = []`，站点显示"（本周无重大平台逻辑变更）"。
- 位置：趋势研判之后、启示之前。

### 3.4 ④ 对 GEO 方案商的产品 / 销售启示
**2–4 条**可落地的产品 / 销售动作，与趋势对应，无序列表；每条一句话说清"做什么 + 为什么"（对应哪个趋势 / 数据），避免空泛。

## 4 JSON 格式（`data/weekly/YYYY-MM-DD_YYYY-MM-DD.json`，文件名 = `{week_start}_{week_end}`）

```json
{
  "week_start": "YYYY-MM-DD", "week_end": "YYYY-MM-DD",
  "overview": {"total": 0, "by_category": {"行业政策": {"count": 0, "pct": 0.0}}, "note": "仅整周 0 条时填"},
  "trends": [{"text": "趋势一句话", "refs": ["条目 id"]}],
  "platform_changes": [{"dimension": "信源引用逻辑|收录周期|生态绑定|爬虫可发现性", "text": "", "refs": ["条目 id"]}],
  "implications": ["对方案商的产品/销售启示"]
}
```
| 字段 | 规则 |
|---|---|
| `week_start` / `week_end` | 周一 / 周日，`week_end = week_start + 6 天` |
| `overview.total` | 区间内日报条目总数（= 6 类 `count` 之和） |
| `overview.by_category` | 6 类全列；`pct` 为 **0–1 小数**（站点展示时转整数百分比） |
| `trends` | 3–5 条；`text` 非空；`refs` 1–3 个，均为该周内存在的 `id`；`total = 0` 时可为空 |
| `platform_changes` | `dimension` 仅 4 个名称之一，同一维度至多一次；`refs` 0–2 个（有变化的维度 1–2 个，无变化 0 个），均为该周内 `id` |
| `implications` | 字符串数组，2–4 条（`total = 0` 时可为空） |

## 5 程序自动检查项（提交前）

| 编号 | 检查项 | 处置 |
|---|---|---|
| W01 | JSON 可解析；字段齐全；`week_start` 为周一、`week_end` = `week_start` + 6；文件名一致 | 阻断 |
| W02 | `overview.total` = 区间内日报条目总数；`by_category` 含 6 类且 `count` 之和 = `total`；`pct` ≈ `count/total`（容差 0.01）；`total = 0` 时全为 0 | 阻断 |
| W03 | `trends` 3–5 条（`total = 0` 可为空）；`refs` 1–3 个且 `id` 均存在于该周日报条目 | 阻断 |
| W04 | `platform_changes`：`dimension` 合法不重复；`refs` 的 `id` 均在该周内；该周存在平台动态条目时 4 个维度应齐全，有变化的维度 `refs` 1–2 个；该周无平台动态条目时应为空数组 | 阻断 |
| W05 | `platform_changes[].refs` 应多数为 `category = 平台动态` 的条目 | 告警 |
| W06 | `implications` 2–4 条且为非空字符串（`total = 0` 可为空） | 阻断 |
| W07 | `trends[].text` / `implications[]` 不以 `1.` `①` `（一）` 等编号开头，趋势不加分类前缀 | 阻断 |
| W08 | 同一周只能有一个文件；不得覆盖已存在的同区间文件（重跑需显式确认） | 阻断 |
| W09 | 区间内有缺失的工作日（既无日报也无无动态哨兵）→ 数据不连续 | 告警 |

## 6 历史周结迁移（`GEO_周度总结_当前.md` 共 9 期 → `data/weekly/*.json`）

1. **切分**：按标题 `### A至B 周度总结`，A → `week_start`，B → `week_end`。
2. **概览**：`覆盖 … ~ …，共 N 条` 得 `total`；`- 类：N 条（P%）` 得 `count`，`pct = P/100`。**保留原文数值，不按现数据重算**。2026-08-10 前的周结无"平台动态"行，补 `count: 0, pct: 0`。
3. **趋势**：`- ` 开头每条为一条趋势（原文的分类前缀照搬，不改）；其后独立成行的 `[标题](url)` 为代表消息，`refs` 由 URL（先按 `04` 8.3 清洗）与该周日报条目 `links[].url` 匹配得到 `id`；匹配不到的转人工并报告。
4. **平台逻辑变更**：`text` 照搬；`refs` 能匹配则填，否则留空。2026-07-20、07-27、08-03 三周无此段，`platform_changes = []`。
5. **启示**：`**方案商启示**` / `**对 GEO 方案商的产品 / 销售启示**` 下的 `- ` 条目照搬为 `implications`。
6. 历史周结不一定满足第 4 节条数与 `refs` 要求：迁移文件顶层加 `"legacy": true`，豁免 W02 的 `pct` / `total` 校验与 W03 / W04 / W06 / W07（与 `04` 8.4 一致）。
