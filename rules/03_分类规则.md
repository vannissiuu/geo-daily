# 03 分类规则

> 本文件管：每条动态归入 6 类中的哪一类（词表、主类判定与冲突裁决、副类）、"平台动态"的定义与边界与子标签、`category` / `secondary_category` / `platform` / `platform_topic` 字段取值。
> 收不收见 `02`，字段与格式见 `04`，平台清单与检索见 `01`。

## 1 分类体系

1.1 **词表**：`行业政策 / 行业方法论 / 新技术 / 市场动态 / 舆情 / 平台动态`。每条**必须有且仅有一个主类** `category`，另可选填**至多一个副类** `secondary_category`（第 1A 节），两者均不得取词表外的值。
1.2 **兜底**：无法判定的归「**舆情**」。兜底只用于真判不出的情形，不得把"平台动态"误归舆情；纯梳理 / 综述稿、评论稿不再默认归舆情，按 1.5 处理。
1.3 **定义**以第 4 节 C_CAT 原文为准，下表为补充范围 / 典型例，两者合并生效：

| 类 | 补充范围 / 典型例 |
|---|---|
| 行业政策 | 政策、标准、监管、行业倡议 / 治理条例；官方或权威机构的测评认证、标准（如信通院测评、中广协标准、WAIC 倡议） |
| 行业方法论 | 评估体系、能力模型、实操框架、ROI 度量、服务商评测维度；C 类一手实测 / 研究（有方法 + 可复核数据）归此类，对方案商价值最高 |
| 新技术 | 模型 / 架构 / 工具发布（RAG、知识图谱、内容生成引擎、新平台）；**主语是"做 GEO 的工具 / 服务商"**的产品 / 工具发布（Pepper、Cloudflare 的 AEO 看板、GMO Local GEO Dash!、Adobe LLM Optimizer）归此类 |
| 市场动态 | 融资、并购、合作、入局、渠道、出海（如微盟海外版）；第三方机构发布的榜单 / 市场规模 / 服务商排名 |
| 舆情 | 风险、信任危机、黑产、消费者警示、红黑榜、声誉事件；影响 AI 回答引用来源或第三方内容呈现的出版商与平台冲突 |
| 平台动态 | 被优化平台自身的算法、信源、引用、收录、爬虫、商业化策略变更（第 2 节） |

1.4 **主类判定（2026-10-26 改版：先找"核心增量事实"，冲突按 1.5 裁决）**：先过 `02` 第 0A 节 GEO 相关性门槛，再问"**这条消息新增的核心事实是什么**"（即标题所述的那件事），按该事实判主类；不再单纯"按顺序命中即止"。1.5 的冲突裁决优先于下列顺序，下列顺序只用于 1.5 未覆盖的情形（命中即止）：
1. 主语是被优化平台，且变更改变"第三方内容如何被找到 / 选中 / 引用 / 呈现" → **平台动态**；
2. 第三方机构发布的榜单 / 市场规模 → **市场动态**；
3. 服务商自己发布的自榜 → 属 02 的 A 类软文，**不收**；
4. 红黑榜 / 消费警示 → **舆情**；
5. 官方或权威机构的测评认证、标准 → **行业政策**；
6. 服务商自己的产品 / 工具发布 → **新技术**；
7. 融资 / 合作 / 入局 → **市场动态**；
8. 可复用框架 / 评估度量 / 优化打法 / 一手实测研究 → **行业方法论**；
9. 其余新能力 / 新架构 / 新基础设施 → **新技术**；无法判定 → **舆情**。

1.5 **常见冲突的主类裁决（硬性，优先于 1.4 顺序）**：

| 冲突情形 | 主类 | 副类（满足 1A 时填） |
|---|---|---|
| 被优化平台**自己的**规则、条款、使用政策（如 Anthropic 使用政策、Meta 商业条款） | 平台动态 | 行业政策（仅当同时有政府 / 标准组织动作） |
| 政府、标准组织、行业协会、权威测评机构的监管 / 标准 / 测评 | 行业政策 | — |
| 监管处罚 / 执法通报 | 行业政策 | 舆情（有曝光、警示或声誉冲击时） |
| 权威机构公布**对具体服务商**的测评等级 / 认证结果 | 行业政策 | 市场动态 |
| 服务商**首次披露**融资（有轮次或金额），同时发布产品 | 市场动态 | 新技术 |
| 服务商发布产品，顺带提及既往融资 | 新技术 | — |
| 合作 / 签约 / 接入生态本身是核心（谁和谁合作） | 市场动态 | 新技术（合作产出明确的新产品能力时） |
| 合作产出的新产品能力是核心，合作方只是背景 | 新技术 | 市场动态 |
| 有方法、样本与可复核数据的研究 / 实测 / 调查 | 行业方法论 | 市场动态（调查数据反映采用率、预算、规模时） |
| 以研究数据为论据的评论、质疑、争议 | 舆情 | 行业方法论 |
| 第三方研究揭示某平台的行为（如向追踪工具返回污染结果） | 按核心事实：研究为主 → 行业方法论；争议为主 → 舆情 | 平台动态（须填 platform / platform_topic） |
| 基础设施与渠道（Cloudflare、WordPress、零售商 Agent 接口等非被优化平台）的功能 / 规则 | 新技术 | 市场动态（含合作 / 融资事实时） |
| 媒体 / 党媒推出 GEO 产品或语料平台 | 新技术 | 市场动态（含联合发布、接入生态等合作事实时） |
| 纯梳理 / 综述稿（无新事件） | 原则上少收；收则按所梳理事件的主要类别 | 平台动态（梳理的是平台机制时） |

**舆情收窄**：舆情只用于风险、争议、信任危机、黑产、消费警示、声誉事件与观点交锋；不作"评论稿 / 梳理稿"的默认归属。

## 1A 副类 `secondary_category`（2026-10-26 新增）

1A.1 **选填，至多 1 个，不得与主类相同**；取值同 1.1 词表。
1A.2 **填写条件**：原文含有**另一类的独立实质事实**——首次披露的融资金额 / 轮次、一项具体的平台机制变更、一组可复核的研究数据、明确的执法 / 标准动作、明确的合作签约或产品上线。只是"提到了""相关于"不算；**宁缺勿滥**，拿不准就不填。1.5 表中的副类列是最常见的组合，不是必填。
1A.3 **副类为平台动态时**：须同时填 `platform` 与 `platform_topic`（第 3A 节），且平台名或别名须出现在标题或摘要中。
1A.4 **用途**：分类索引中，条目在主类与副类下都出现（副类下标"兼"）；每日动态的分类筛选同时匹配主类与副类。**统计口径只用主类**：周结 `overview.by_category`、`run` 与运行记录中的分类统计一律按 `category` 计，副类不计入。
1A.5 采集日志中每条入选候选写 `category_reason`（`04` 5.1）：一句话说明主类依据（核心事实是什么、按 1.5 哪条裁决），有副类时一并说明副类依据。

## 2 平台动态：定义、边界、判定

2.1 **定义**：被优化平台——`01` 第 5 节平台清单（豆包、DeepSeek、Kimi、千问、文心、元宝、360 纳米搜索 / 360AI、秘塔、抖音 AI 搜索、Google、ChatGPT、Perplexity、Claude、Microsoft Copilot / Bing、Meta AI / Muse、Apple Intelligence）——**自身**的算法、信源、引用、收录、爬虫、商业化策略变更。Cloudflare、xAI、WordPress 等基础设施或模型公司**不算**被优化平台（Cloudflare / WordPress 的动态归新技术）。
2.2 **必须收录**，不得以"模型更新 / 产品发布"为由排除：
  1. 模型对第三方内容的**检索机制**升级（联网检索深度、可调度子 Agent 数、可交叉核验网页数、并发策略）；
  2. **证据溯源 / 引用标注 / 权威信源优选**机制的引入或调整（"证据溯源""权威信源检索""时效判断""数据核验"）；
  3. 引用 / 收录 / 排序 / 推荐位的**规则与权重变更**；
  4. 爬虫协议、robots、收录周期变更；
  5. **AI 回答中的广告位 / 商品卡 / 推荐位 / AI 购物结果呈现**（影响第三方品牌如何被呈现）。
2.3 **排除**（检索阶段即过滤）：与第三方内容呈现无关的履约（寄快递、租房租车等）、支付与订单基建、C 端会员收费、开放 Agent 接入。
2.4 **口诀**：主语是被优化平台**且**变更改变"第三方内容如何被找到 / 选中 / 引用 / 呈现" → 平台动态；主语是被优化平台但只是"自己多了什么功能 / 能卖什么" → 不纳入；主语是做 GEO 的工具 / 服务商 → 产品发布归新技术，融资 / 合作 / 渠道归市场动态。
2.5 **无论有无媒体解读均属强相关**：官方更新日志、开发者文档、爬虫协议变更公告等"静默调整"同样纳入，按 `02` 链接铁律核验后入报。
2.6 **标题须含平台名**（机检项，见 `04`）；网站展示时由 `platform` 字段生成【平台动态-平台】标签，不手工加。
2.7 判例：豆包 2.1 Pro 0915 强化证据溯源与权威信源检索，曾被误当模型更新排除，实为平台动态（按 2.2）；千问开放平台上线属开放 Agent 接入，与 GEO 可见度机制无关，剔除（按 2.3）。

## 3 `platform` 字段（主类或副类为平台动态时填，其他条目省略或填空字符串）

3.1 **标准取值**：`豆包`、`DeepSeek`、`Kimi`、`千问`、`文心`、`元宝`、`360`、`秘塔`、`抖音`、`Google`、`ChatGPT`、`Perplexity`、`Claude`、`Copilot`、`Meta AI`、`Apple Intelligence`；涉及多个平台且无法拆分填 `多平台`。
3.2 **归并**：OpenAI 产品 → `ChatGPT`；Gemini / AI Mode / AI Overviews / Discover / Google 搜索 → `Google`；文心一言 / 百度 AI 搜索 → `文心`；Bing / Microsoft Copilot → `Copilot`；Muse → `Meta AI`。
3.3 **标题须含该平台名或其别名**（OpenAI、Gemini、谷歌、字节、Anthropic、通义、百度、Bing 等，别名表见 `config/sources.json` 的 `platform_aliases`）。多个平台各自独立成事件则拆成多条（各有独立信源）；不能拆的填 `多平台`，标题写出主要平台名。

## 3A `platform_topic` 平台动态子标签（2026-10-26 新增）

3A.1 **何时填**：主类或副类为平台动态的条目**必填**，其他条目不填（省略或空字符串）。只填 1 个，取变更最核心的方面。
3A.2 **取值**（`config/sources.json` 的 `platform_topics`）：

| 取值 | 含义 | 典型例 |
|---|---|---|
| 引用与呈现 | 被引来源在答案中如何展示、排序、链接、标注 | AI Overviews 引用卡片显示 AI 摘要；内联链接上移；偏好信源侧栏 |
| 检索与收录 | 联网检索、索引、信源选择与权威信源机制 | DeepSeek / 元宝搜索开放；证据溯源与权威信源优选 |
| 爬虫与抓取 | 爬虫、robots、抓取条款与收录周期 | Meta 商业条款抓取企业网站；Googlebot / robots 变更 |
| 广告与商业化 | AI 答案中的广告位、赞助内容、广告创意与投放市场 | ChatGPT 广告扩市场、创意增强；AI Mode 广告 |
| 购物与交易 | 商品卡、购物推荐、结账与交易闭环、购物 Agent | 豆包内嵌直播间下单；ChatGPT 购物追问框；Muse 购物 Agent |
| 测量与数据 | 平台提供或影响的流量 / 引用数据与归因 | ChatGPT UTM 变更；Bing 网站管理员工具 AI 报告 |
| 规则与治理 | 平台自己的使用政策、反操纵与内容规则 | Anthropic 禁止伪造出处的使用政策 |

3A.3 子标签与周结 `platform_changes` 的四个维度（`05` 3.3）相互独立：子标签按单条消息标注，周结维度按当周归纳。

## 4 网站原样展示：分类说明（C_CAT.md 原文，冻结，不改一字）

```
<callout emoji="💡">
分类说明：
- 行业政策：监管 / 标准 / 治理 / 权威倡议与执法
- 行业方法论：可复用框架 / 评估度量 / 优化打法 / 研究基准
- 新技术：新能力 / 新架构 / 新基础设施 / 技术范式转移
- 市场动态：融资 / 并购 / 合作 / 上市 / 新玩家入场 / 规模 / 榜单 / 出海 / 渠道。
- 舆情：风险 / 争议 / 信任危机 / 黑产 / 消费者警示 / 红黑榜 / 声誉事件
- 平台动态：被优化对象（豆包 / DeepSeek / Kimi / 千问 / 文心 / 元宝 / Google / ChatGPT / Perplexity / Claude 等大模型平台）自身的算法、信源、引用、收录、爬虫、商业化策略变更。
</callout>
```
说明：`<callout>` 为飞书语法，前端取其中 emoji 与文字即可。该文本是**展示文案，不是判类依据**；判类依据是第 1–3 节（含兜底与"工具归新技术"）。
